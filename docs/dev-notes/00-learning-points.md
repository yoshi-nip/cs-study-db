# 開発メモ（ジュニア向け・学習ポイント）

## 目的
開発を進める中でつまずきやすい点や、理解しておくと役立つポイントを記録する。

## 1. プロジェクト初期化（01-scaffold）
- **npmと依存関係**: `package.json` が何を管理しているか理解する
- **Viteの役割**: 開発サーバとビルドの違いを把握

## 2. UI基盤（02-ui-foundation）
- **MUIの考え方**: デザイントークン（色/余白/タイポ）をテーマで統一
- **ThemeProviderの意味**: 全体の見た目を一括管理できる

## 3. データ設計（03-data-model）
- **JSONと型定義**: まずデータ形を決めてからUIを作ると迷わない
- **スキーマの粒度**: 1スライド=1テーマに合わせた最小構造

## 4. レイアウト & ルーティング（04-layout-routing）
- **SPAの動き**: ページ遷移は「画面の差し替え」
- **責務分離**: 章一覧/本文/用語パネルはそれぞれ分ける

## 5. スライド表示（05-slide-view）
- **アニメーションは最小から**: まずフェード1種類で良い
- **状態管理**: 現在の章とスライド番号の関係を整理する

## 6. 用語解説UI（06-glossary-ui）
- **短文と詳解の分離**: ツールチップは短く、詳解は右パネル
- **再利用性**: 用語ボタンは共通コンポーネント化

## 7. コンテンツ投入（07-content-fill）
- **文章の密度**: 1枚あたりの情報量を絞る
- **用語リンク**: スライド内で用語に誘導できる構成にする

## 8. 仕上げ（08-polish-docs）
- **レスポンシブ**: 幅が狭い時の崩れを先に想定
- **README整備**: 立ち上げ手順を明確にする

## よくある詰まりポイント
- MUIのテーマが反映されない → `ThemeProvider` の位置を確認
- ルーティングが効かない → `BrowserRouter` の適用範囲を確認
- 型エラーが多い → まずデータ形を固定してから型定義
