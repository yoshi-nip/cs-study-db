# 09. 開発時の注意事項（ガイドライン）

## 基本方針
- 関数やコンポーネントの責務は小さく単純にする
- 可読性と保守性を優先する
- フロントのみでも拡張を意識した構造にする
- 開発メモは「実装内容・意図・学習ポイント・つまずき」を明記する

## 関数設計
- 1関数 = 1責務
- 早期returnでネストを浅くする
- 命名は「何をするか」が分かる動詞ベース

## コンポーネント設計
- 1コンポーネント = 1目的
- 表示とデータ取得/整形は分離する
- 再利用できる部分は共通化（UIパーツ）

## 開発メモ（MD）運用
- 章ごとにMDを分けて記録する
- できる限り同じフォーマットで統一する（必要なら崩してもOK）
- MUIなどの使用要素は具体名と役割まで書く
- 実装の考え方（なぜその形にしたか）を必ず書く
- コミットメッセージ案まで記載する
- 型の当てはめ（`as` など）は「なぜ必要か」をジュニア向けにMDとコードコメントで補足する(使用MUIや他のコードなども同様)

## DRY（重複排除）
- 似たUIは共通コンポーネントに寄せる
- 共通ロジックは hooks/utils に寄せる
- 早すぎる抽象化は避ける

## 依存性の扱い（DI/疎結合）
- 依存は引数で渡す（propsで注入）
- グローバル参照を避ける
- テストしやすい形に分ける

## 状態管理
- ローカルstateで足りるならそれを使う
- コンポーネントの責務を超える状態は上位へ引き上げる

## 型とデータ
- JSON構造とTypeScript型は同期させる
- 型が曖昧ならまずtype定義を作る
